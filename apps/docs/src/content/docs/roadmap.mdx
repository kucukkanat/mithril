Mithril's docs describe only what's **verified against the source today**. This page tracks the
scoped work that isn't shipped yet, so you never hit a surprise `NOT_IMPLEMENTED`.

<Aside type="tip">
Everything under "Shipped" below is implemented and covered by the test suite. Everything under
"Next" and "Later" is designed but not yet built.
</Aside>

## Shipped today

- **Core** — the `MithrilEvent` protocol, total `reduce`/`replay`, `narrow()`, the streaming
  agent loop, and the `agentLoop` eject hatch.
- **Tools & agents** — typed tools via Standard Schema, three run methods (`run`/`stream`/`resume`).
- **Providers** — OpenAI, Anthropic, Google, DeepSeek, and OpenRouter adapters (real SSE), self-wiring
  handles, byok/proxy/ephemeral transports, plus **browser-local inference** via Transformers.js
  (`@mithril/providers/transformers` — on-device WebGPU/WASM, no keys). DeepSeek and OpenRouter speak the
  OpenAI wire format, so they share its serializer and SSE parser (`deepseek-reasoner` additionally streams
  a `reasoning` channel; OpenRouter takes optional `appUrl`/`appName` attribution).
- **Human-in-the-loop** — all three suspension tiers: Tier-1 approval (`needsApproval`), Tier-1b (a tool
  _returns_ `suspend(...)`), and Tier-2 (`await ctx.suspend()` mid-execute, resumed by replaying journaled
  effects). Resume with `resume()` (to a final `RunResult`) or `resumeStream()` (streaming), plus in-process
  `RunHandle.resolve()`. `seal`/`open` sealing (HMAC + AES-GCM) for persisted tokens.
- **Run control** — real `RunHandle.cancel()` (aborts at the next step boundary), `iterate()` step-level
  snapshots, and `asTool()` to call one agent as another's tool — with **first-class nested HITL**: a
  suspended sub-agent is resumed through the parent's own token.
- **Structured output** — validate → retry, streamed `object.delta`.
- **Self-correction & reliability** — a **pluggable self-healing middleware stack** (`healing.defaults()`,
  toggled by the `healing` field): deterministic parse-repair + one visible schema coercion
  (`healing.argRepair` → `tool.repair`), a bounded per-tool re-ask budget (`healing.retryBudget` →
  `tool.retry`, then a clear terminal error), identical-call **loop detection** (`healing.loopGuard` →
  `loop.detected`, steer-then-halt), structured-output re-ask (`healing.outputRetry` → `object.invalid`),
  plus loop-level `outputSchema` enforcement, token/cost **budget guards**
  (`maxTokens`/`maxCostMicroUsd` → `budget.exceeded`), a `ToolErrorClass` taxonomy on the wire,
  crash-hardening (provider/middleware throws → typed `run.error`), and opt-in test-time compute
  (`selfConsistency`, `bestOfN`). See [Self-correction](/guides/self-correction/).
- **Composability** — **step-, model-, tool-, and finalize-altitude** middleware, plugins, event consumers.
- **Memory** — `Checkpointer` (in-memory + Bun SQLite) with a conformance kit, drivable automatically by
  the loop for zero-glue durable runs (`run(input, { persistence })` + `resumeFrom`).
- **Providers** — a Standard-Schema → JSON-Schema converter (`toJsonSchema`/`withJsonSchema`) feeds real
  tool-parameter schemas to every adapter (OpenAI/Anthropic/Google/DeepSeek/OpenRouter) when the input
  schema self-describes or a converter is supplied.
- **MCP** — a client, an official Streamable-**HTTP transport** (`@mithril/mcp/http`), and **server
  exposure** (`@mithril/mcp/server`) to serve your own tools over MCP.
- **Devtools** — a headless inspector **and a framework-agnostic UI** (event stream, span tree, cost +
  context meters, time-travel scrubber, all-tier suspension card) shipped as a **Web Component**
  (`@mithril/devtools/element`), **mount functions** (`@mithril/devtools/dom`), and **React** components
  (`@mithril/devtools/ui`) over one rendering implementation — with **zero-touch attach**
  (`import "mithril/devtools/attach"` / `MITHRIL_DEVTOOLS=1`) and a `BroadcastChannel` live-tail panel.
- **Batteries** — OTel spans, `fs`/`kv` (in-memory + IndexedDB) adapters, the `vectors` store (in-memory +
  durable Bun SQLite), the `sandbox` code runner (`node:vm`, a cross-runtime `worker` backend, and a remote
  proxy), workflows, React bindings, `create-mithril`.
- **Self-authored tools** (`@mithril/authoring`) — the agent defines its own tools mid-run, approval-gated.
  Tier-1 **composition** (a linear pipeline over tools the agent already has — authority-preserving, with
  inherited approval) runs everywhere; Tier-2 **sandboxed scripts** are opt-in behind a `CodeRunner`.
  Backed in core by a **live per-run tool registry** (one snapshot per step, so what the model is offered is
  exactly what dispatches), `tool.registered` / `tool.revoked` events that make `replay(log)` reconstruct
  the registry, an implemented `Plugin.setup` / `PluginHost`, `RunTokenV3` so authored tools survive a
  cross-process resume, and `fromJsonSchema`. Optional persistence via `kvToolStore` / `fsToolStore`.
  See the [guide](/guides/self-authored-tools/).
- **Per-tool timeouts** — `Tool.timeoutMs` bounds one `execute`, producing a `"timeout"`-classified
  `tool.error` and aborting that call's `ctx.signal`.
- **Client-side MCP input validation** — an MCP server's `inputSchema` is compiled with `fromJsonSchema`,
  so the model sees a tool's real parameters and bad arguments fail locally instead of costing a round-trip.
- **Studio (M1)** — a client-only studio app (`apps/studio`): design agents in structured panels **and** a
  fully two-way TypeScript code view (`@mithril/spec` — codegen + real-compiler parse with lossless
  verbatim regions), run them in-browser against live BYOK providers or on-device models via the shared
  worker runner (`@mithril/runner-web`, also powering the docs playground), with the devtools inspector,
  chat multi-turn, HITL approvals, and IndexedDB project persistence. See the
  [Studio guide](/guides/studio/).

## Next

| Area | What's coming | Why it's not here yet |
| --- | --- | --- |
| Adapters | ANN-indexed `vectors` backends (sqlite-vec / pgvector / Vectorize); a WASM `sandbox` backend | today's `vectors` do an exact brute-force scan; the local `sandbox` backends (`node:vm`, `worker`) are isolation, not security |
| Tool authoring | `ToolSearchPolicy` (`topK` + `rank`) to narrow a large registry per step; routing composition sub-calls through the tool middleware chain; a `test_tool` dry-run | every registered tool costs tokens on every step, so today a `maxTools` cap plus `revoke_tool` is the budget control; composition steps are visible as `tool.progress` but are not wrapped by `Middleware.tool` |
| Studio | Free-form multi-agent canvas, share URLs & TS-project export | the Studio ships today as a client-only app (design → run, two-way code view); the canvas and sharing land next |

## Later

- **Realtime / voice** (v2).
- **A `bunx mithril dev` CLI wrapper** for the Studio (local-project awareness) — the hosted static
  Studio is the shipping form; a CLI wrapper is out of scope for now.
- **Local-inference upgrades** — a WASM/CPU-guaranteed backend (wllama) and native constrained/grammar
  decoding for hard structured-output guarantees on local models.
- **Promoting an authored tool to source** — codegen a proven self-authored tool into a real `.ts` file via
  `@mithril/spec`, for human review and commit. Deliberately not shipped: it turns a runtime feature into a
  build-time one, needs a writable checkout, and would make `@mithril/spec` a runtime dependency of the loop.

<Aside type="note">
This ordering reflects the current build plan and can change. The design for most of these already
lives in the in-repo spec — see [How Mithril was designed](/design/how-mithril-was-designed/).
</Aside>
